先亮账本：一张 0 元的月账单

一个人做公司，最先被劝花钱的地方就是工具。教程看多了，好像不买几个订阅、不上几套付费软件，这事就没法开工。我把自己的工具账本盘了一遍：从博客托管到内容生产再到视频渲染，工具现金成本是每月 0 元，这个状态已经持续三个月。

逐层摊开。托管这一层，博客放在 GitHub Pages 上，零费用，连域名都不用买；这三个月里只出现过发布后几分钟的 CDN 缓存延迟，没有一次真正的宕机。生产这一层，写作、脚本、多平台改写，全是我自己搭的流程，跑在本地环境里，没有买过任何订阅；视频渲染也是本地方案，配音、字幕、合成一条命令跑完。分发这一层，各平台发布本来就不花钱，花的是每天 30 秒复制粘贴的时间。三层加起来，就是一张 0 元的月账单。

一人公司早期最稀缺的不是钱，是把免费方案用透的耐心。

三层免费替代：钱到底省在哪里

第一层：用免费基础设施替代付费托管

静态内容——文章、页面、文档——根本不需要买服务器。GitHub Pages、对象存储的免费额度，足够一个人用很久。很多人上来就买云服务器，一个月几十上百块，跑的其实是一个没有人访问的静态站。这是新手段最常见的白花钱：为想象中的流量规模，预付了想象中的基础设施。

第二层：用本地工具替代云端订阅

能本地跑的就不上云。我的经验是：先在本地手搓一个能跑的版本，用满两周，再判断这个能力是不是真的高频刚需——是，再考虑付费升级；不是，一个免费的半成品也够用了。绝大多数工具需求死在这一步：你以为要用很多年，实际上两周后就想不起来了。

第三层：用判断力替代工具（最值钱的一层）

很多付费工具卖的其实是「决策」——帮你决定写什么、什么时候发、数据好不好。但这些判断恰恰是一人公司最不该外包的部分。我的选题有固定队列，数据有固定台账，判断标准全部写死在文件里。判断力免费，但要求你肯花时间把规则写下来。规则写下来的那一刻，工具 list 里就少了一个为「帮你决定」付费的订阅。

免费的真实代价：三条，挨条说

别把这篇读成「免费颂」。免费方案的账，另一面长这样。

代价一：时间换钱。免费方案的搭建成本全部折算成你的时间。博客自动部署那套脚本，第一次调通花了不止一个晚上。按市场时薪折算，它未必比付费方案便宜——它便宜的前提，是这套东西你会一直用下去，成本被长期摊薄。

代价二：没有客服，文档就是一切。出问题只能自己啃文档、查社区、翻源码。上个月博客部署的验证环节卡过一次，排查花掉的时间如果折算成客服工时，早超了任何订阅费。免费方案对一个人的要求是：你得有耐心做自己的技术支持。

代价三：没有捷径。付费工具给的「一键」「模板」「智能推荐」，本质是把新手坑提前填平。手搓方案必须自己把每个坑踩一遍——这是学费，不是浪费，但确实慢。

免费便宜的前提是长期用、成本被摊薄；只用两周就吃灰的东西，免费反而是最贵的。

三条付费触发线：按时付费、按瓶颈付费

所以我的立场不是「永远免费」，是「按时付费、按瓶颈付费」。三条触发线写死在账本里：

  • 触发线一（真瓶颈付费）：免费方案连续两周成为流水线的真实瓶颈，且没有免费替代可换——为这一个瓶颈付费，不是为「可能用到」付费。
    • 触发线二（高频刚需付费）：某个能力被 30 天调用记录验证为高频刚需，本地版维护成本已超过订阅费——换付费版，把时间省下来。
      • 触发线三（确定性付费）：涉及合规与安全的环节，免费方案能力不够时，优先为确定性付费——这类钱省不得。

      三条线之外的所有付费冲动，一律写进「观察区」，冷静两周再说。三个月下来，观察区里没有一条活到了付费那天——大部分「刚需」在第二周就自己消失了。

      你今天就能照做的五步

      • 第一步：把过去三个月的所有工具支出列成一张表，多少条都行，先列全；
        • 第二步：每条旁边写上真实使用次数——查记录，不凭印象；
          • 第三步：标出「付了费但 30 天没用过」的条目，这类是第一优先处理对象；
            • 第四步：给每个还在用的免费方案写一句「它省了什么、代价是什么」，代价超过省下的就进观察区；
              • 第五步：把三条付费触发线抄下来贴在工作区，之后每一次想付费，先对线再掏钱。

              那张支出表会直接告诉你：下一次该不该掏钱。工具账单的数字不重要，重要的是每一笔钱都花在已经验证的瓶颈上，而不是花在「开工的仪式感」上。
